Софтфон используется для звонков с рабочего места сотрудника. Приложение регистрируется на IP-АТС под внутренним
номером пользователя, по которому контакт-центр связывает пользователя 1С с его рабочим телефоном.

Для работы можно использовать любой SIP-клиент. Ниже приведен пример настройки **MicroSIP (издание МИКО)**.

## Перед началом

Проверьте, что выполнены базовые настройки телефонии:
- модуль интеграции установлен на IP-АТС;
- в IP-АТС создан внутренний номер сотрудника и известен пароль SIP-учетной записи;
- в карточке пользователя 1С указан тот же внутренний номер. Подробнее см. раздел [Пользователи и права доступа](../administration/users_and_rights.md);
- на рабочем месте подключены гарнитура или микрофон с наушниками.

!!!warning Сетевой доступ
Рабочая станция должна иметь доступ к IP-АТС по SIP и RTP. Если между пользователем и IP-АТС есть NAT,
VPN или межсетевой экран, проверьте маршрутизацию и правила фильтрации заранее.
!!!

## Установка MicroSIP

MicroSIP можно установить вручную на рабочем месте пользователя или централизованно через групповые политики Windows.

>>> Скачайте дистрибутив MicroSIP
Откройте в 1С форму подключения софтфона: [!badge Контакт-центр] :icon-chevron-right: [!badge Сервис] :icon-chevron-right: [!badge Подключение софтфона].
Ссылка для скачивания дистрибутива расположена внутри инструкции.

>>> Установите приложение
Запустите файл `MicroSIP-X.Y.Z.msi`, где `X.Y.Z` - версия поставляемого файла.

Права администратора не требуются: при ручной установке приложение устанавливается в профиль текущего пользователя.

>>> Настройте учетную запись
Запустите MicroSIP и добавьте новую SIP-учетную запись. Вы можете заполнить параметры подключения вручную. Однако для
пользователей, не имеющих доступа к настройкам АТС, будет удобнее заполнить их автоматически. Нажмите кнопку
[!badge Авто настройка] и вставьте ссылку из формы подключения софтфона в 1С.

Сохраните настройки и убедитесь, что MicroSIP зарегистрировался на IP-АТС. В строке состояния приложения должно
отображаться успешное подключение.
>>>

## Централизованная установка через GPO

Этот способ подходит для домена Active Directory, когда MicroSIP нужно установить сразу на несколько рабочих станций.
Пакет назначается на компьютер и устанавливается при загрузке Windows для всех пользователей машины.

>>> Разместите MSI на сетевом ресурсе
Скопируйте `MicroSIP-X.Y.Z.msi` в общую папку на файловом сервере, например:

```text
\\<файловый-сервер>\Distrib\MicroSIP\MicroSIP-X.Y.Z.msi
```

Назначьте права на папку и сетевой ресурс. Установка выполняется от учетной записи компьютера, поэтому доступ нужен
компьютерам домена:

{.compact}
Учетная запись | Права
--- | ---
`Domain Computers` | Чтение
`SYSTEM` | Полный доступ
`Domain Admins` | Полный доступ

!!!warning UNC-путь
В политике указывайте только UNC-путь вида `\\сервер\шара\...`. Локальный путь к MSI приведет к ошибке установки
на клиентских компьютерах.
!!!

>>> Создайте объект групповой политики
1. Откройте оснастку [!badge Управление групповой политикой] (`gpmc.msc`).
2. Создайте новый объект GPO, например `MicroSIP Deployment`.
3. Откройте его на редактирование:
   [!badge Computer Configuration] :icon-chevron-right: [!badge Policies] :icon-chevron-right:
   [!badge Software Settings] :icon-chevron-right: [!badge Software installation].
4. Выберите [!badge New] :icon-chevron-right: [!badge Package] и укажите UNC-путь к MSI.
5. В качестве метода развертывания выберите [!badge Assigned].

>>> Проверьте параметры пакета
В свойствах пакета MicroSIP откройте вкладку [!badge Deployment] :icon-chevron-right: [!badge Advanced] и включите
[!badge Ignore language when deploying this package].

Это необходимо, чтобы Windows не пропускала установку на рабочих станциях с языком ОС, отличным от языка MSI-пакета.

>>> Включите обработку политики при запуске Windows
Для Windows 10 и Windows 11 рекомендуется включить синхронную обработку групповых политик при старте.
В том же GPO откройте:

[!badge Computer Configuration] :icon-chevron-right: [!badge Policies] :icon-chevron-right:
[!badge Administrative Templates] :icon-chevron-right: [!badge System] :icon-chevron-right: [!badge Logon].

Параметр [!badge Always wait for the network at computer startup and logon] установите в значение [!badge Enabled].

>>> Привяжите GPO к рабочим станциям
Привяжите созданный объект групповой политики к OU, в котором находятся нужные компьютеры.

Если нужно ограничить установку частью рабочих станций, используйте фильтрацию безопасности: добавьте группу
с нужными компьютерами и назначьте ей права `Read` и `Apply group policy`.
>>>

## Проверка подключения

После установки и настройки софтфона выполните проверку:
1. Перезагрузите рабочую станцию, если установка выполнялась через GPO.
2. Убедитесь, что MicroSIP запущен и зарегистрирован на IP-АТС.
3. Выполните тестовый исходящий вызов из MicroSIP.
4. Выполните исходящий вызов из 1С по клиенту или контакту с заполненным номером телефона.

Если MicroSIP установлен через GPO, наличие приложения можно проверить на рабочей станции командой:

```powershell
Test-Path "C:\Program Files (x86)\MicroSIP\microsip.exe"
```

Также можно убедиться, что политика применена к компьютеру:

```cmd
gpresult /scope computer /r
```

В списке `Applied Group Policy Objects` должен отображаться объект политики, через который устанавливается MicroSIP.

## Диагностика

MicroSIP не установился через GPO
: Проверьте, что в пакете указан UNC-путь к MSI, у компьютеров есть право чтения сетевой папки, включен параметр
`Ignore language when deploying this package`, а политика применяется к OU с рабочими станциями.

Политика применилась, но установка не началась
: Назначенное на компьютер ПО устанавливается при загрузке Windows. Выполните перезагрузку рабочей станции.
Для Windows 10 и Windows 11 также проверьте параметр
`Always wait for the network at computer startup and logon`.

Софтфон не регистрируется на IP-АТС
: Проверьте адрес IP-АТС, внутренний номер, логин, пароль SIP-учетной записи и доступность SIP/RTP с рабочего места.

Звонок из MicroSIP проходит, а из 1С не начинается
: Проверьте, что у пользователя 1С указан внутренний номер, совпадающий с SIP-учетной записью софтфона.
